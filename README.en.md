# 📷 ESP-RC Cam: FPV Vision for your RC Car

Welcome to the ESP-RC Cam repository! This project is the camera module of the ESP-RC Car system, built on an AI-Thinker ESP32-CAM module with an OV2640 sensor. It streams live video over Wi-Fi in MJPEG format directly to the car brain's webapp, giving your RC a true first-person view.

This module is designed to work alongside **[esprc-brain](../esprc-brain/)**, but can also be used standalone from any web browser.

## ✨ Key Features

-   **Live MJPEG Streaming:** Smooth video transmission over standard MJPEG on **port 81**. Compatible with any browser or video player. The brain webapp displays it with a simple `<img>` — no extra JavaScript needed.

-   **WebSocket Streaming:** Alternative binary JPEG frame channel over WebSocket (`/ws`), used by the brain webapp for advanced integration.

-   **Automatic Integration with esprc-brain:** The brain discovers the camera automatically via **mDNS** (hostname `esprc-cam.local`) every 30 seconds — no manual IP configuration required.

-   **Embedded Web Interface:** Web app built into the firmware with 4 tabs: Live Stream, Image Config, Wi-Fi Connection, and OTA Update.

-   **Full Image Configuration:** Real-time adjustment of resolution (QQVGA to UXGA), JPEG quality, brightness, contrast, saturation, exposure, AWB, AGC, lens correction, mirror and flip, and more.

-   **Sync from Brain:** A button in the Connection tab that automatically pulls Wi-Fi credentials from the brain, making initial setup on local networks effortless.

-   **OTA Updates:** Update the camera firmware wirelessly from the "Update" tab — includes a progress bar and confirmation dialog.

-   **Pure ESP-IDF Firmware:** Written in C++ on ESP-IDF 6.0 with no Arduino dependencies. Dual OTA partition for safe updates.

-   **Connectivity Modes:**
    -   **Access Point (AP):** The camera creates its own `ESPRC-CAM` Wi-Fi network for direct access.
    -   **Station (STA):** The camera connects to your local network, ideal for integration with the brain.

## 🚀 Getting Started

### Prerequisites

1.  **Hardware:**
    -   **AI-Thinker ESP32-CAM** module (ESP32, OV2640 sensor, 4 MB flash, 4 MB PSRAM).
    -   **FTDI adapter** (USB-to-serial) for flashing: connect `TX→RX`, `RX→TX`, `GND→GND`, `3.3V→3.3V` (or 5V depending on your board). To enter flash mode, connect **GPIO0 → GND** before powering on, then press RST.

2.  **Software:**
    -   [ESP-IDF v6.0.1](https://docs.espressif.com/projects/esp-idf/en/v6.0.1/esp32/get-started/index.html): Espressif's development framework (required version: **v6.0.1**).
    -   [Node.js and npm](https://nodejs.org/): to build the webapp (only if you want to modify it).
    -   [Git](https://git-scm.com/): to clone the repository.

### Setting Up the Firmware

1.  **Clone the repository:**
    ```bash
    git clone https://gitlab.com/falmon/esprc-cam.git
    cd esprc-cam/Firmware
    ```

2.  **Activate the ESP-IDF v6.0.1 environment** (required in every new terminal session):
    ```bash
    . /path/to/esp-idf-v6.0.1/export.sh
    ```
    > If you installed IDF using the official installer, use the `export.sh` script from your local installation.

3.  **Set the target** (once per clone):
    ```bash
    idf.py set-target esp32
    ```

4.  **Build the firmware:**
    ```bash
    idf.py build
    ```

5.  **Flash the ESP32-CAM:**
    Connect GPIO0 to GND, press RST to enter flash mode, then run:
    ```bash
    idf.py -p /dev/ttyUSB0 flash monitor
    ```
    Release GPIO0 once the transfer begins. The serial monitor will show boot logs.

> **Note:** If this is your first flash or you changed the target, delete `sdkconfig` to force regeneration: `rm -f sdkconfig`

### WebApp Development (Optional)

The webapp uses **Gulp.js** to bundle everything (HTML, CSS, JS) into a single `index.html` that gets embedded in the firmware binary.

1.  **Install dependencies:**
    ```bash
    cd Firmware/webapp
    npm install
    ```

2.  **Available commands:**
    -   `npm run build`: Compiles and copies `index.html` to `Firmware/main/`. Then rebuild and flash the firmware to apply changes.
    -   `npm run serve`: Local server at `http://localhost:8080` for developing without flashing.
    -   `npm run clean`: Deletes build artifacts.

> **Note:** The bundler uses `gulp-inline-source` with `compress:true`, which **does not support optional chaining (`?.`) or nullish coalescing (`??`)**. Always use explicit `&&` guards instead.

## 🔧 Usage Guide

### First Connection

By default, the ESP32-CAM boots in **Access Point (AP) mode**.

1.  **Connect to the Wi-Fi network:** Look for the network **`ESPRC-CAM`** (no password) from your phone or PC.
2.  **Open the web interface:** Navigate to [http://esprc-cam.local](http://esprc-cam.local) or [http://192.168.4.1](http://192.168.4.1).
3.  **Watch the feed!** You're on the Stream tab. Press ▶ to start the stream.

### Web Interface Guide

The webapp has 4 tabs accessible from the sidebar (desktop) or the bottom navigation bar (mobile).

---

#### 📹 Stream

The main tab. Shows the live video feed from the camera.

-   **▶ Start / ■ Stop:** Connects or cuts the MJPEG stream.
-   **Fullscreen:** Button in the corner of the image for fullscreen view, with a live FPS badge overlay.
-   **Status badge:** Shows whether the stream is active or offline.

> The stream uses the browser's native `<img>` element pointing to `http://{ip}:81/mjpeg`. No JavaScript is needed to play it — the browser handles it natively.

---

#### ⚙️ Config

Full OV2640 sensor configuration. All changes are saved to the ESP32's NVS memory and applied on restart.

**Stream:**
| Parameter | Description |
|-----------|-------------|
| Resolution | From QQVGA (160×120) to UXGA (1600×1200). QVGA (320×240) by default. |
| Quality | JPEG compression: 4 (best quality) to 63 (highest compression). |
| FPS Limit | Caps frames per second (0 = unlimited). |
| FPS Stats | Enables real-time FPS counter visible on the stream. |

**Image:**
| Parameter | Description |
|-----------|-------------|
| Brightness | -2 to +2 |
| Contrast | -2 to +2 |
| Saturation | -2 to +2 |
| H-Mirror | Flips the image horizontally. |
| V-Flip | Flips the image vertically. |

**Advanced Settings** (collapsible):
Manual exposure (AEC), gain (AGC), white balance (AWB), lens correction, special effects, WB mode, and more — fine controls for specific lighting conditions.

---

#### 📡 Connection

Network configuration for the device.

**Wi-Fi:**
-   **Mode:** Choose between **Access Point** (camera creates its own network) or **Wi-Fi Client** (camera connects to an existing network).
-   **SSID / Password / Hostname:** Network credentials and mDNS device name (`esprc-cam` by default).
-   **Save & Restart:** Applies network changes and reboots automatically.
-   **Sync from Brain:** Queries the brain via mDNS and automatically downloads the Wi-Fi credentials stored on it. Perfect for setting up the camera on the same network as the brain with a single click.

**Device:**
-   Shows the current IP address of the ESP32-CAM.
-   Buttons to **Restart** or perform a **Factory Reset** (clears all saved configuration).

---

#### 🔄 Update

OTA (Over The Air) firmware update — no cables needed.

1.  Check current firmware information (active partition, version, build date).
2.  Select the `esprc_cam.bin` binary generated by `idf.py build` in `Firmware/build/`.
3.  Press **Upload & Reboot**. A progress bar tracks the upload.
4.  Once complete, the device reboots automatically with the new firmware.

> **Warning:** Uploading invalid firmware can brick the device until it is reflashed via USB.

## 🔗 Integration with esprc-brain

This module is designed to complement **[esprc-brain](../esprc-brain/)**. Integration is fully automatic:

1.  **Auto-discovery:** The brain runs `discover_camera_task` (FreeRTOS, every 30 s) which queries mDNS for `esprc-cam`. When the IP is found, it is stored in NVS and exposed at `GET /api/camera`.

2.  **Brain webapp auto-connect:** When the brain webapp loads, it calls `/api/camera` and connects the MJPEG stream automatically if the camera is available on the network.

3.  **Camera config from the brain:** The "Camera" tab in the brain webapp sends requests directly to `http://{camIP}/api/config`. The brain does not proxy — the browser connects directly to the camera.

4.  **Real-time stats:** The brain webapp polls `http://{camIP}/api/stats` every 2 s while the camera tab is open.

5.  **Recommended flash order:** Flash the camera **first** so the brain can discover it on startup.

For more details on the integration, see [../CLAUDE.md](../CLAUDE.md).
